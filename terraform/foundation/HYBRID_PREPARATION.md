## 이번 단계

현재 설정 조회 결과와 팀 입력을 바탕으로 후속 Hybrid 코드 준비 항목을 정리한다.
내부 주소, 장비별 경로, 비밀값, 실제 실행 입력은 이 문서에 포함하지 않는다.
실제 값은 승인된 보호 입력 경로에서 대조한다.

## 작업 순서

1. 관측된 현재 상태와 목표 설정을 구분하고 담당별 입력 수신 여부를 확인한다.
2. AWS 운영체제·AMI·인스턴스 규격·디스크·OS 관리 방식을 확인한다.
3. 관련 공통 입력의 소유자를 확인하고 중복 선언을 피한다.
4. Terraform 자원 정의와 실행에 필요한 최소 IAM 권한을 준비한다.
5. Ansible 설정의 영구 유지·멱등성·복구 방법을 준비한다.
6. 정적 검사 및 PR 리뷰·병합을 진행한다.
7. 최신 main 기준 권한 반영과 전체 Plan·Cost Gate·팀 실행 조건을 확인한다.
8. 승인된 실행 후 실제 통신·허용/거부·복구를 검증한다.

## 담당 경계

- Network/Hybrid: 연결 설정·기반 자원·실행 권한 Source 준비.
- Data: 작업 VM·서비스 설정 및 접속 계약 공급.
- 통합: 같은 foundation Root/State를 사용하며 담당 영역 단독 Apply로 분리하지 않는다.
- 정상 Cloud 서비스는 Hybrid 장애에 의존하지 않는 상위 기준을 유지한다.

## VPN 서버 설정·키 공급 준비

### 관리 범위

- Terraform foundation은 EC2·ENI·EIP·SG·Route와 서버용 SSM Role/Profile을 관리한다.
- 서버 내부의 WireGuard·IP Forwarding·Host Firewall은
  Ansible 또는 승인된 초기 설정 절차 중 하나를 관리 주체로 정한다.
- 같은 설정을 여러 도구가 중복 관리하지 않는다.
- SSM은 서버 관리 접속 수단이며, 그 자체가 VPN 설정 코드의 관리 주체는 아니다.

### 준비할 설정과 확인 기준

| 항목 | 준비할 내용 | 실제 적용 후 확인 |
|---|---|---|
| SSM | Agent 설치·실행 및 관리자의 접속 권한 | 정상 관리 접속, WireGuard 중단 중 관리 접속 |
| WireGuard | 설치·Peer·AllowedIPs·서비스 자동 실행 | Handshake와 재부팅 후 연결 |
| IP Forwarding | 승인된 Gateway의 IPv4 전달 기능 | 현재 값과 재부팅 후 유지 |
| Host Firewall | 승인된 DB 통신과 응답 허용, 미허용 전달 차단 | 허용·거부 시험과 원본 Source IP |
| 개인키 공급 | 보호 보관·대상 서버 공급·출력 억제 | 서버 밖 복원본으로 재공급 가능 여부 |
| 인계 | 설정 담당·실행 순서·검증 결과·복구 절차 | 다른 실행자가 문서대로 재현 |

### 비밀값과 실행 경계

- WireGuard 개인키는 Git·Terraform user_data·Plan·State·Output에 평문으로 넣지 않는다.
- 기존 Valkey Token이나 백업용 age 개인키를 WireGuard 키로 재사용하지 않는다.
- 공개 설정과 개인키 공급을 구분하고, 실패 시 로그에도 개인키를 남기지 않는다.
- 온프렘 기존 Route·방화벽 규칙은 유지하며 필요한 변경만 준비한다.
- 서버 설정의 최종 도구·실행 방법과 키 공급 절차는 구현 전 검토한다.

현재는 준비 목록 기록이다.
서버 설정 구현·적용·키 공급·복원·통신 검증 완료를 의미하지 않는다.
