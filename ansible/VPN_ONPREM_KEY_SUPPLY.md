
# 기존 온프렘 키 공급 코드 후보

현재 단계는 코드 후보와 모의시험 준비다.
실제 키 복호화·서버 공급은 실행하지 않는다.

## 파일 역할

- vpn_onprem_key_supply.py: Controller에서 기존 암호문을 복호화하고 SSH로 공급하는 후보.
- vpn_key_install_remote.py: 서버 대상·서비스·키 대응·파일 보호 조건을 확인하는 후보.
- test_vpn_key_supply.py: 가짜 키와 임시 폴더를 사용하는 검사 10개.

## 확인할 동작

정상 공급, 기존 파일 보존, 키 짝 불일치 차단, 연결 파일 차단,
기록 실패 시 신규 파일 정리, 기존 폴더 권한 보존을 확인한다.

## 실제 적용 전 남은 조건

Controller Linux에서 10개 검사 통과와 코드 리뷰·병합이 필요하다.
실제 공급은 별도 실행 단계에서 대상·Source·서비스·파일 상태를 확인한 뒤 수행한다.
이 후보의 준비·시험 성공은 실제 공급 성공을 뜻하지 않는다.

개인키는 실제 실행 시 Controller 메모리와 SSH 암호화 채널을 거쳐
서버 메모리와 서버 보호 파일에 공급된다.
Python 메모리의 확실한 소거까지 보장하는 방식은 아니다.

SSH 결과 수신이 불확실하면 서버에 파일이 만들어졌을 수 있으므로
자동 재실행하지 않는다.

실패 과정에서 새로 만든 빈 보호 폴더는 남을 수 있다.
기존 폴더 권한을 자동으로 바꾸거나 서비스를 시작하지 않는다.

## 기록 경계

기존 키 생성·복구 검사와 기존 원복 모의시험 7개를 재실행하지 않는다.
새 키 공급 코드에 대한 별도 검사다.

## 실행과 검사 시 자동 생성 파일

공급 프로그램은 모듈을 가져오기 전에 바이트코드 기록을 비활성화한다.
Git에서는 __pycache__/ 및 *.pyc를 자동 생성 파일로 제외한다.
기존 캐시나 서버 파일은 이 보완에서 삭제하지 않는다.

검사는 python3 -I -B로 실행한다.
기존 키 공급 검사 10개·저장소 검사 5개는 기존 근거에 연결한다.
이번 보완의 새 실행 흐름 검사는 test_vpn_supply_flow.py의 6개다.
실제 복호화·SSH 대신 가짜 결과를 사용한다.

## 실패 안내 구분

SSH를 시도하기 전 중단되면 이 실행에 의한 서버 변경은 없다.
표시된 단계의 조건을 해결한 뒤 실행 여부를 다시 판단한다.
SSH 실행을 시도한 뒤 실패하면 부분 공급 여부를 먼저 확인한다.
원본 오류·비밀값은 출력하지 않고 고정된 단계 이름만 안내한다.

## 실제 SSH 접속 전 조건

현재 코드는 기존 조회에 사용한 root 직접 접속을 기준으로 한다.
실제 공급 전에 root 접속 허용 여부와 대상·호스트 키를 확인한다.
Controller의 SSH 설정은 대상 주소·인증 방식에 영향을 줄 수 있다.
실제 사용할 설정과 인증 경로를 확인한 후 공급한다.
비밀번호·개인키 암호 입력이 필요하면 터미널에서만 입력한다.
새 인증정보를 Git이나 명령행 인자에 넣지 않는다.

CI 연결·서버 main의 차단 사례 확대·상위 폴더 fsync 보완은 후속 개선이다.
이 기록은 실제 키 공급이나 접속 성공을 의미하지 않는다.
